# Checks a drafting pass could not map, and why.

Carried out of the staging files by tools/merge_proposals.py so the
reason survives the merge — a check nobody could map is a finding
about the catalogue, and losing the reason means rediscovering it.

- **CKV2_AWS_16** (misc.yml) — Needs a fixed-enum argument on the list call. application-autoscaling DescribeScalableTargets REQUIRES ServiceNamespace, and both routes to it are closed: aws_api_assets calls the list operation with no arguments at all, and the vendored aws_application_autoscaling_scalable_targets runs validate_parameters(required: %i(service_namespace)) and raises "service_namespace must be provided" when the generated enumeration calls it as <plural>(aws_region: region). `parent:` does not substitute — it supplies a discovered parent id, and ServiceNamespace is a constant. The identifier spaces would reconcile if it were reachable (DescribeScalableTargets keys on ResourceId 'table/my-table', which terminal_segment reduces to the table name aws_dynamodb_tables yields), so this is one enum argument away, not a redesign.
- **CKV2_AWS_21** (misc.yml) — BLOCKED BY THE MERGE GATE **AND** BY A RENDERER GAP. An earlier version of this entry said "blocked only by the merge gate, exactly as CKV2_AWS_39". That was wrong, and wrong in the direction this repo cares about. The right side is a two-step spec, and render_membership emits NO parent-failure guard: parent_guard_for is wired into API_TEMPLATE only and MEMBERSHIP_TEMPLATE never mentions `parent`, which was confirmed on the rendered artefact — with the gate patched in a throwaway copy, controls/CKV2_AWS_21.rb renders without a single occurrence of `parent_failures`. So one GetGroup that throttles or is denied silently removes that group's whole membership from the right side, and every user in it is then reported "not a member of any IAM group": a total finding manufactured from an API error, with nothing in the control saying so. IAM's rate limit makes that likely on a large account rather than exotic. All three membership joins already live are one-step on both sides, which is why the gap has never bitten. DO NOT LAND THIS ON THE TWO-LINE GATE FIX ALONE — it also needs render_membership to assert each side's `parent_failures` and count them towards `applicable`, as parent_guard_for does for the api reader. Everything else about the mapping is confirmed against the SDK in the image: iam list_users and list_groups both take no required arguments; get_group REQUIRES group_name, which is precisely the `parent:` shape (parent list_groups -> groups -> group_name, arg group_name, child get_group -> users); every one of list_users, list_groups and get_group is pageable (Aws::Pager on marker/is_truncated), so a group with more than one page of members is followed rather than truncated; and both the ListUsers `users` member and the GetGroup `users` member are the SAME User shape carrying [path, user_name, user_id, arn, ...]. So both sides speak the identical IAM user ARN and the join is verbatim-to-verbatim with no reduction at all, which is the strongest form this shape has. Corrects tools/proposals/graph.yml, which concluded "no reader answers which groups is this user in" — true of the vendored pack, but the question can be asked from the other side, and get_group is reachable now that a child list call can take a parent id. The draft is at the foot of this file, marked NOT READY: the gate fix unblocks the merge, and the renderer gap above is what still has to be closed before the control means what it says.
- **CKV2_AWS_28** (misc.yml) — Two independent blockers, and the SDK is not one of them — aws-sdk-wafv2 is in the image. First, there is no wafv2 resource in the vendored pack (the only WAF resources are WAF Classic, a different service with a different id space) and aws_albs/aws_alb expose no WebACL association. Second, the call that would answer it per load balancer, wafv2 GetWebACLForResource(ResourceArn), is on a DIFFERENT CLIENT from the elbv2 call that enumerates the parents; aws_api_assets builds exactly one client per spec and issues both the parent and the child call on it, so the two-step feature that landed cannot span the two services. wafv2 ListWebACLs is closed for the separate reason that it requires Scope. It also wants a left-side scope (internet-facing only) that membership does not have.
- **CKV2_AWS_31** (misc.yml) — Needs a fixed-enum argument on the list call, on BOTH sides. wafv2 ListWebACLs and ListLoggingConfigurations each REQUIRE Scope (REGIONAL or CLOUDFRONT), confirmed against the SDK input shapes, and aws_api_assets invokes the list operation with no arguments. aws-sdk-wafv2 is in the image and this is otherwise the cleanest join in the whole set — left speaks a WebACL ARN, right keys on the same ARN, verbatim to verbatim with no reduction — so it is the one to build first once a spec can declare a constant argument. It would then also need running twice, once per Scope, which is a shape question of its own.
- **CKV2_AWS_33** (misc.yml) — Blocked at the SDK, the only check in this slice of which that is true: aws-sdk-appsync is not in tools/image_gems.txt, and merge_proposals and lint_api_specs both refuse a spec naming an absent gem because the LoadError is rescued into unreadable_regions and the control reads as Not Applicable. The wafv2 half carries the Scope blocker described under CKV2_AWS_31 on top of that.
- **CKV2_AWS_38** (pc-b.yml) — Route 53 DNSSEC. Needs absent_errors:. route53.GetDNSSEC rejects PRIVATE hosted zones outright and answers DNSSECNotFound for an unsigned public zone -- and children_of records any raising child as a parent_failure. In a normal account that is one loud failure per zone instead of a DNSSEC verdict, with private zones (out of scope for the check) indistinguishable from unsigned public ones (the finding). The parent leg is fine: ListHostedZones is global and no-argument, and HostedZone.Id comes back as "/hostedzone/Zxxxx", which GetDNSSEC accepts. Telling the two rejections apart also needs Config.PrivateZone from the PARENT row, which the flattening does not carry.
- **CKV2_AWS_39** (misc.yml) — BLOCKED ONLY BY THE MERGE GATE, not by the data. The membership mapping is complete, both api specs are field-confirmed against the SDK (Route53 list_hosted_zones and list_query_logging_configs both take no required arguments; HostedZone carries [id, name, caller_reference, config, resource_record_set_count, linked_service, features] with config.private_zone nested; QueryLoggingConfig carries [id, hosted_zone_id, cloud_watch_logs_log_group_arn] and has NO arn member, so the join keys on hosted_zone_id), and the identifier spaces are reconciled — left is "/hostedzone/Z123" reduced by terminal_segment, right is the bare "Z123" verbatim, both sides global so both key on the region literal "global". tools/merge_proposals.py refuses it: SHAPE_REQUIRED has no 'membership' key, so the reader is rejected as unknown, and a membership mapping carries no `satisfies`, so it would then be told "satisfies 'equals' needs a value". render_controls.render_membership, lint_resource_map.check_membership and libraries/_checkov_membership.rb all support the shape; only the gate does not. Fix is two lines in merge_proposals.py (add "membership" to SHAPE_REQUIRED and to VERBLESS_READERS). Ready-to-merge draft is in the comment block at the foot of tools/staging/misc.yml. One divergence to carry with it: Route 53 accepts query-logging configurations for PUBLIC zones only, and membership has no left-side scoping (gap_3), so every private hosted zone will report uncovered. Checkov's own graph check has the same blind spot, so this matches Checkov rather than exceeding it — but it is a known false-finding class and should be said in the control, not discovered in the results.
- **CKV2_AWS_47** (misc.yml) — Three hops and an assertion about the MATCHED RIGHT ROW, which is the membership shape's other declared gap: `every_left_covered` is the only assertion implemented, and "follow the reference, then assert about what it points at" is named in resource_map.yml's header as deliberately not built. The rule names it needs (AWSManagedRulesAnonymousIpList, AWSManagedRulesKnownBadInputsRuleSet) are only on GetWebACL(Name, Scope, Id) — three arguments, one of them a fixed enum — never on ListWebACLs. Identifier hazard worth recording for whoever does build it: CloudFront's DistributionSummary.WebACLId is a WAFv2 ARN for wafv2 and a bare id for WAF Classic, so the two sides do not always speak the same identifier even within one account.
- **CKV2_AWS_5** (misc.yml) — Needs a LIST-VALUED join key, which the membership shape does not have and which fails silently if faked. The only deployed evidence that a security group is attached to anything is ec2 NetworkInterface.Groups, an ARRAY of GroupIdentifier nested inside each ENI row. aws_api_assets#dig_path breaks the walk at any node that is not a Hash, so a field path of 'groups.group_id' reads nil for every ENI; naming 'groups' whole is worse, because CheckovMembership#checkov_membership_key does `raw = "#{row[field]}"` and would key every ENI on the STRING FORM of an array of structs, which matches no security group id and reports every group unattached. The stock shape cannot do it either: the singular aws_ec2_network_interface requires network_interface_id and cannot be looked up by group id.
- **CKV2_AWS_70** (policy.yml) — Not reachable with any existing shape, and not a policy_document problem. The check is about apigateway METHODS: it needs GetRestApis -> GetResources(restApiId) -> GetMethod(restApiId, resourceId, httpMethod), a three-level parent chain, and only then narrows to OPTIONS methods with AuthorizationType NONE and ApiKeyRequired false. The policy document is a FALLBACK arm of the verdict (a PRIVATE endpointConfiguration or a resource policy can excuse an unauthorized method), not the question, so aws_policy_documents cannot answer it even with an apigateway source added: the reader enumerates one collection and evaluates one predicate per asset, and there is no arm in it for "the parent's endpoint configuration decides whether the child is in scope". Needs the parent_child shape at three levels plus a combined verdict; belongs with the graph work, not here.
- **CKV2_AWS_76** (misc.yml) — Same missing assertion form as CKV2_AWS_47 (assert about the referent's rule names, not about the link) on top of the cross-client blocker described under CKV2_AWS_28. Recorded because it is the closest of the WAF set: the identifiers already line up — aws_albs.load_balancer_arns yields exactly the ResourceArn that wafv2 GetWebACLForResource takes, and that call needs no Scope — so what is missing is a spec that can issue a per-id LOOKUP against a second service's client, plus the referent assertion.

- **CKV_AWS_120** (pc-b.yml) — API Gateway stage caching. DOWNGRADED ON REVIEW -- the one mapping this slice's own drafter could not confirm, and the unconfirmed half is the half that decides whether the control can fail at all. Stage.CacheClusterEnabled EXISTS on the GetStages item shape (confirmed against the aws-sdk-apigateway in sparc-auditor:v0.5.0), but nothing available offline says whether API Gateway RETURNS it as false for a stage with caching off or simply omits it. Omitted is not a harmless outcome here: dig_path answers nil, `equals` IS nil-filtered, in_scope goes empty, and API_TEMPLATE's `applicable` -- which is `!in_scope.empty? || !unreadable.empty? || unusable.positive? || !parent_failures.empty?` -- goes false, so every stage in the estate renders Not Applicable and the check reports as a rule that does not apply rather than one that cannot fire. That is exactly the silence-as-success shape this repo exists to refuse, and 'the member exists in the model' is not evidence against it. The live CKV_AWS_73 mapping asserts a sibling boolean on the same call and its note claims 'AWS returns it for every stage' -- an ANALOGY, not a confirmation of this member. Unblock it with one live GetStages against a stage with caching off; if the response carries cacheClusterEnabled: false, restage verbatim (spec and field are already correct and already live).
- **CKV_AWS_143** (misc.yml) — Needs a per-asset follow-up call (s3 GetObjectLockConfiguration(Bucket)) and two spec keys that are named in tools/api_specs.yml as deliberately not built: `region_field`, because S3 answers 301 unless a per-bucket call is issued against the bucket's own region, and `absent_errors`, because GetObjectLockConfiguration raises ObjectLockConfigurationNotFoundError when lock was never enabled — which is the FAILING state and would otherwise be recorded as a parent failure. The header is explicit that an S3 two-step spec must not ship before region routing exists. The stock reader cannot stand in: the vendored aws_s3_bucket makes second calls for encryption, versioning, logging and lifecycle but has no object-lock method.
- **CKV_AWS_144** (pc-b.yml) — S3 sub-resource, and blocked on TWO unimplemented reader features at once. (1) region_field: ListBuckets is global but every per-bucket call must be issued against the bucket's OWN region or S3 answers 301 PermanentRedirect; a scope: global spec builds one client and would 301 on most buckets, landing every one in parent_failures. (2) absent_errors: s3.GetBucketReplication's ReplicationConfigurationNotFoundError is raised exactly when the bucket is NON-COMPLIANT, and children_of records a raising child as a parent_failure, so the entire failing population would arrive as an error list instead of as findings. Separately, the deployed assertion would be weaker than the check's name: it can show replication is configured but not that the destination is in another REGION, because Destination.Bucket is a region-less S3 ARN and resolving it is a third level. Spec drafted in tools/proposals/parentchild.yml; do not stage it until both features exist, because a half-implemented version reads as a clean scan.

- **CKV_AWS_165** (pc-a.yml) — aws_dynamodb_global_table. WITHDRAWN AFTER REVIEW — this was drafted as a mapped two-step spec (parent dynamodb.ListGlobalTables -> child DescribeContinuousBackups(TableName), collection continuous_backups_description, id _parent, field point_in_time_recovery_description.point_in_time_recovery_status == ENABLED). Every member name in that draft is real and correctly spelled; the spec is still not shippable, for two reasons independent of each other. (1) THE PARENT LEG IS NOT REGION-SCOPED AND THE CHILD LEG IS, so the control fails a COMPLIANT account. ListGlobalTables takes an OPTIONAL RegionName parameter — "Lists the global tables in a specific Region" (AWS API Reference) — and the spec schema has no way to put a literal argument on the parent call at all (`args:` is listed as NOT IMPLEMENTED in tools/api_specs.yml, and is child-side even when it lands). So the call goes out with no RegionName in every region of the walk, and the operation's own summary line — "Lists all global tables that have a replica in the specified Region" — names a Region that was never specified. AWS does not document a fallback to the endpoint's region. If there is no such fallback, then in every region holding no replica the parent leg returns the account's global tables anyway and the child DescribeContinuousBackups raises TableNotFoundException — which is in that operation's declared error set, confirmed on the model. children_of records that per parent in parent_failures, and the generated control asserts parent_failures is empty, so a single v1 global table with PITR correctly enabled in both replica regions FAILS the control once per region it is not replicated into. Loud rather than silent, but wrong, and wrong on the compliant case. This is the same defect tools/api_specs.yml already documents under "parent region routing" for S3 — "an S3 two-step spec will record a parent failure per bucket — loud and wrong, which is the safe direction, but do not ship it that way." The rule applies here unchanged. (2) THE PARENT LEG TRUNCATES SILENTLY. Confirmed on the model: Client.api.operation(:list_global_tables)[:pager] is nil, and the output shape carries last_evaluated_global_table_name — an operation that declares a continuation token and has no paginator to drive it. each_page wraps it in a NullPager and yields exactly one page. The AWS API Reference documents Limit as "if the parameter is not specified DynamoDB defaults to 100", so global table 101 onward is never enumerated, never assessed, and absent renders as Not Applicable, which is a claim. That is the same defect that skips CKV_AWS_240 and CKV_AWS_241 below (firehose, ten per region); the only difference is the size of the bound, and "no account will reach 100 deprecated global tables" is an assumption about the account, not a property of the reader. Do NOT redraft this with parent ListTables instead: that enumerates every table in the region, duplicating CKV_AWS_28 (live, stock reader, aws_dynamodb_table.point_in_time_recovery) while failing ordinary tables under a rule whose subject is global tables. Two further things to carry forward if a parent-side literal-argument capability lands and this is re-opened. First, PointInTimeRecoveryDescription is OPTIONAL on ContinuousBackupsDescription — confirmed, required is [continuous_backups_status] alone — so a response omitting it yields a nil field, the control's nil filter drops the row, and the control renders Not Applicable instead of failing; that needs confirming against a real response before it ships. Second, do not assert continuous_backups_status instead: it is ENABLED for every table that exists, so a control built on it could never fail. Worth recording either way: Checkov's own CKV_AWS_165 is a placeholder whose scan_resource_conf returns PASSED unconditionally, so any deployed version of this rule is the only one that assesses anything.

- **CKV_AWS_213** (coll-a.yml) — aws_load_balancer_policy. The SDK model is fine — a two-step off describe_load_balancers -> describe_load_balancer_policies resolves, and policy_attribute_descriptions[].{attribute_name,attribute_value} are real members. The roll-up is withdrawn because it rests on an UNVERIFIABLE runtime claim in the direction that fails silently. `none_of` over policy_attribute_descriptions with [attribute_name in the weak Protocol-* list, attribute_value == 'true'] only ever fails if the LB-scoped DescribeLoadBalancerPolicies EXPANDS a reference policy into Protocol-* attributes. Checkov has a separate Reference-Security-Policy branch precisely because that is how these are written, and the fix this repo would recommend (aws_load_balancer_policy with a single Reference-Security-Policy policy_attribute) produces exactly the shape whose expansion is in doubt. If ELB does NOT expand, a policy pinned to ELBSecurityPolicy-2015-05 carries no Protocol-* attribute at all, `none_of` is vacuously TRUE, and the control passes having assessed nothing — with no diagnostic, because the collection-scope guard only asks whether SOME asset exposed policy_attribute_descriptions and every stickiness / backend-auth policy on the account satisfies it while contributing no protocol evidence. Reinstating this needs either (a) one recorded LB-scoped DescribeLoadBalancerPolicies response from a policy created via Reference-Security-Policy, proving the expansion, or (b) a second condition arm [attribute_name == Reference-Security-Policy, attribute_value in <weak policy names>] — which is expressible under the conjunction, but only against a deny-list of AWS predefined policy names that no SDK model can confirm and that goes stale silently. Neither is available in this slice.
- **CKV_AWS_219** (pc-b.yml) — CodePipeline artifact-store CMK. DOWNGRADED ON REVIEW: the mapping was staged with a DECLARED false positive, and a control that reports a finding against a compliant resource is not an acceptable trade for coverage in an evidence pipeline. A CROSS-REGION pipeline carries `artifactStores` -- a MAP keyed by region, confirmed as ArtifactStoreMap on GetPipeline's PipelineDeclaration in the aws-sdk-codepipeline the image ships -- and no `artifactStore` at all. dig_path walks dotted paths over hashes and cannot address an open-keyed map, so artifact_store.encryption_key.id is nil, `not_empty` does NOT nil-filter, and the pipeline FAILS however well every regional store is encrypted. Nothing in the schema can scope it back out: there is no conditional_scope and no disjunction, and the only escape left to an operator is an exempt_assets entry, which is a suppression and needs owner approval. The single-region half is sound and fully confirmed -- artifact_store.encryption_key.{id,type} all resolve, and CodePipeline omits encryptionKey entirely for the default S3 key, so not_empty genuinely distinguishes CMK from default. Restage the whole thing once the reader can express a map-valued path (the `map_keyed` gap). The aws_codepipeline api spec is withdrawn with it rather than left orphaned.
