# Checks a drafting pass could not map, and why.

Carried out of the staging files by tools/merge_proposals.py so the
reason survives the merge — a check nobody could map is a finding
about the catalogue, and losing the reason means rediscovering it.

- **CKV2_AWS_1** (graph-a.yml) — REMOVED BY THE ADVERSARIAL PASS — needs a where-guard, and without one it penalises its own remediation. Every element of the mapping verifies: aws_network_acls registers :network_acl_ids, aws_network_acl requires network_acl_id, associated_subnet_ids is a public method returning [], and NetworkAclAssociation.SubnetId is confirmed in botocore. The defect is population, not plumbing. DescribeNetworkAcls returns the VPC DEFAULT network ACL, which Terraform never declares as aws_network_acl (it is aws_default_network_acl) and which Checkov therefore never evaluates. In AWS a subnet always sits on exactly one ACL, so the moment every subnet in a VPC is explicitly associated with a custom ACL — which is precisely the state this control's own fix produces — that VPC's default ACL has zero associations and FAILS, while being correctly configured. A subnet-less VPC fails the same way. That is the identical "a control that fails correct configuration is worse than no control" objection this slice used to skip CKV2_AWS_15, and consistency requires the same verdict. Unblocked cheaply: aws_network_acls already registers a :default column and the singular has a default? predicate, so `where default == false` is all this needs. Remediation, preserved so the next pass need not rederive it: declare aws_network_acl with subnet_ids = [for s in aws_subnet.private : s.id] plus explicit ingress/egress blocks; out of band there is no "attach" call, only `aws ec2 replace-network-acl-association --association-id <assoc-id> --network-acl-id <acl-id>`, and because an ACL is stateless a missing ephemeral-port egress rule breaks return traffic the instant the swap lands.
- **CKV2_AWS_12** (graph-a.yml) — Not a single field. VPCHasRestrictedSG.json requires NINE attributes absent across BOTH the ingress and the egress block, and the schema asserts exactly one property. It also needs a `where group_name == "default"` — the only enumeration available is aws_security_groups, and without that guard the control asserts that every security group in the account has no ingress rules, which is absurd rather than strict. A freshly created VPC's default SG always carries one self-referencing ingress rule AND one allow-all egress rule, so asserting inbound_rules alone would pass a VPC that is in fact wide open outbound. Needs: a where-guard plus multi-property assertion.
- **CKV2_AWS_15** (graph-a.yml) — Needs a where-guard. AutoScallingEnabledELB.json filters on `aws_autoscaling_attachment within` — it evaluates ONLY auto scaling groups that are attached to a load balancer. The api_spec itself is buildable (autoscaling DescribeAutoScalingGroups takes no required arguments and returns HealthCheckType, LoadBalancerNames and TargetGroupARNs on one row, and aws-sdk-autoscaling is in the image), but with no `where load_balancer_names or target_group_arns is non-empty` the control asserts HealthCheckType == ELB on every standalone ASG, every one of which correctly uses EC2 health checks and would fail. A control that fails correct configuration is worse than no control.
- **CKV2_AWS_16** (graph-joins.yml) — Not expressible in either direction. The plural aws_application_autoscaling_scalable_targets does validate_parameters( required: %i(service_namespace)) and then explicitly raises "service_namespace must be provided", so the generated enumeration — which calls it as <plural>(aws_region: region) — would raise rather than enumerate (trap 2). The singular speaks a service NAMESPACE, not a table name. And the identifiers differ anyway: aws_dynamodb_tables yields "my-table" while DescribeScalableTargets keys on ResourceId "table/my-table". The api reader cannot serve the right side either, since it passes no arguments to the list call.
- **CKV2_AWS_18** (graph-joins.yml) — Same blocker as CKV2_AWS_8: AWS Backup is reachable (gem in the image, aws_backup_vault spec already live, ListProtectedResources needs no arguments), and what is missing is the two-enumeration join shape. The EFS side is clean on its own — aws_efs_file_systems registers file_system_ids, and tools/api_specs.yml DOES already carry an aws_efs_file_system row whose arn is file_system_arn, correcting an earlier note that said it did not — but there is nothing to join it to. Checked whether EFS answers this without Backup: it does not — DescribeFileSystems carries no backup policy, and describe_backup_policy is not called anywhere in the pack, so aws_efs_file_system exposes nothing about backups.
- **CKV2_AWS_2** (graph-a.yml) — REMOVED BY THE ADVERSARIAL PASS — as drafted it is not a port of CKV2_AWS_2, it is a second copy of CKV_AWS_3. The proposed mapping (aws_ebs_volumes .volume_ids -> aws_ebs_volume#encrypted equals true) is element-for-element identical to the entry ALREADY LIVE in resource_map_derived.yml under CKV_AWS_3, so the two controls can never return different verdicts and the second one adds no information — it only double-counts every unencrypted volume in the aggregated failure summary that feeds the OSCAL pipeline. The single thing that distinguishes Checkov's graph check from CKV_AWS_3 is the attachment exemption (EncryptedEBSVolumeOnlyConnectedToEC2s passes an unattached unencrypted volume), and that is exactly what was dropped. The result is a control tagged checkov_id CKV2_AWS_2 that reports FAIL on the one population Checkov reports PASS on, which breaks reconciliation against Checkov for anyone diffing the two. A note disclosing the divergence does not stop the HDF result carrying the id. Unblocked cheaply: aws_ebs_volumes registers an :attachments column, so `where attachments not empty` is the whole fix — the same missing where-guard as CKV2_AWS_12 and CKV2_AWS_15. Remediation, preserved: encrypted = true plus kms_key_id on aws_ebs_volume, and aws_ebs_encryption_by_default for volumes created outside Terraform; note that an existing volume cannot be encrypted in place (snapshot, copy the snapshot with --encrypted, create a volume from the copy, stop the instance and swap the attachment — downtime, not a setting change) and that `aws ec2 enable-ebs-encryption-by-default` is per region and only affects volumes created after it.
- **CKV2_AWS_21** (graph-joins.yml) — No reader answers "which groups is this user in". aws_iam_user exposes access keys, attached/inline policies, MFA and login profile — no groups — and aws_iam_users registers no group column; list_groups_for_user appears nowhere in the pack. Reversing the direction (enumerate aws_iam_groups, assert aws_iam_group(group_name:).users is not empty) is a DIFFERENT check: it answers CKV2_AWS_14 (no empty groups) and would pass an account whose users are all outside every group.
- **CKV2_AWS_27** (graph-joins.yml) — No reader returns RDS cluster parameter VALUES: describe_db_cluster_parameters appears nowhere in the pack, and there is no aws_rds_cluster_parameter_group resource at all. The left side is broken too — aws_rds_clusters registers cluster_identifier, database_name, cluster_members, engine, engine_version, status, allocated_storage, storage_encrypted, availability_zones, multi_az and arn, and no parameter-group column. Separately, Checkov's own assertion is vacuous when assessed against a deployed cluster: it only checks the parameter NAMES are present, and DescribeDBClusterParameters returns every engine parameter with its default, so a faithful port is a control that cannot fail (trap 6). The honest deployed check is on the VALUE (log_statement != 'none'), which is a different assertion and needs the reader that does not exist.
- **CKV2_AWS_28** (graph-joins.yml) — No wafv2 resource in the vendored stock pack — the only WAF resources are WAF Classic (aws_waf_web_acl and friends), a different service with a different id space. aws-sdk-wafv2 IS in the image, so the gem is not the blocker. aws_albs/aws_alb expose no WebACL association (confirmed against their full column list and attr_readers), so the left side alone cannot answer it. The api reader cannot supply the right side either: both wafv2.list_web_acls and wafv2.list_resources_for_web_acl take arguments and aws_api_assets calls public_send(list) with none. GetWebACLForResource would fit the per-id shape — left yields a load balancer ARN and that call takes a ResourceArn — but there is no resource or spec that makes the call.
- **CKV2_AWS_30** (graph-joins.yml) — Instance-level twin of CKV2_AWS_27 and blocked the same way. describe_db_parameters is not called anywhere in the pack, and aws_db_parameter_group runs create_resource_methods over the DescribeDBParameterGroups row, which carries only DBParameterGroupName, DBParameterGroupFamily, Description and DBParameterGroupArn — metadata, no parameters. Same vacuity: name-presence passes for every deployed instance.
- **CKV2_AWS_31** (graph-joins.yml) — The proposal's reference join, and the cleanest one — matched on the WebACL ARN with no key translation — but it is unbuildable here: there is no wafv2 resource in the stock pack, and — the binding constraint, since aws-sdk-wafv2 is in the image — BOTH of its calls (ListWebACLs, ListLoggingConfigurations) require Scope, confirmed against botocore, which aws_api_assets cannot pass. Left speaks a WebACL ARN and the right side keys on the same ARN, so this is the one to build first once a wafv2 reader that accepts a fixed-enum argument exists.
- **CKV2_AWS_32** (graph-a.yml) — Needs a dotted collection path the api reader does not implement. DefaultCacheBehavior.ResponseHeadersPolicyId is on cloudfront.DistributionSummary, but AwsApiAssets#collect resolves `collection` with a single `page.public_send(@spec["collection"])` (libraries/aws_api_assets.rb:145) and CloudFront nests its items under distribution_list.items. The stock plural registers no such column and the stock singular never reads the field. Unblocked by one dig_path call in AwsApiAssets#collect, which is a library change, not a data change.
- **CKV2_AWS_33** (graph-joins.yml) — Same wafv2 blocker as CKV2_AWS_28, and the AppSync side is worse: no stock resource, no api spec, and no aws-sdk-appsync in tools/image_gems.txt. merge_proposals refuses an api spec naming a gem the image lacks, because a LoadError is rescued into unreadable_regions and the control then reads as Not Applicable. So this one is blocked at the SDK — the only entry in this slice of which that is true.
- **CKV2_AWS_35** (graph-a.yml) — Needs a new predicate on aws_route_table, and the obvious shortcut is a trap. The plural FLATTENS routes into parallel per-column arrays (destination_cidr_block: [...], gateway_id: [...], instance_id: [...]), so the pairing between a route's destination and its target is LOST: a table with a 0.0.0.0/0-via-NAT route and a 10.0.0.0/8-via-instance route is indistinguishable from the failing case. Only the singular keeps the pairing, via create_resource_methods over the raw hash, and reading it requires a predicate over `routes` that no satisfies verb expresses.
- **CKV2_AWS_37** (graph-a.yml) — Needs a new two-call reader. CodecommitApprovalRulesAttached.json wants the aws_codecommit_approval_rule_template_association connection; deployed that is ListAssociatedApprovalRuleTemplatesForRepository, which takes a repositoryName — a second per-asset call that neither the stock shape nor the api reader (one list call, no per-item call) performs. Worth asking whether it earns the build at all: CodeCommit is closed to new AWS accounts, so this is likely a permanently zero-asset control.
- **CKV2_AWS_38** (graph-a.yml) — Needs a new two-call reader. There is NO hosted-zone resource in the vendored inspec-aws pack at all — only aws_route53_record_sets, which requires a zone id (trap 2). An api_spec over route53 ListHostedZones would enumerate zones, but HostedZone carries no DNSSEC state: signing status comes from GetDNSSEC per zone, a second per-item call the api reader does not make. It also needs a where-guard on Config.PrivateZone == false, since GetDNSSEC errors on a private zone and Checkov exempts private zones too.
- **CKV2_AWS_39** (graph-joins.yml) — No route53 query-logging reader: list_query_logging_configs appears nowhere in the pack, and there is no api spec for it. The identifiers also differ and the mismatch is silent — aws_hosted_zones.ids yields "/hostedzone/Z123…" while route53 QueryLoggingConfig.HostedZoneId is the bare "Z123…", so an unnormalised join matches nothing and reports every zone as unlogged, which renders as a total finding rather than as an error.
- **CKV2_AWS_41** (graph-a.yml) — Expressible today only through a reader that would produce false failures. EC2InstanceHasIAMRoleAttached.json is a plain attribute check (iam_instance_profile exists) and the field is right there on DescribeInstances, but the only stock enumeration is aws_ec2_instances, whose fetch_data applies no state filter — so it returns TERMINATED and shutting-down instances, which AWS keeps returning for up to an hour and which have no instance profile. Every recently terminated instance would render a FAIL. The profile's own aws_compute_assets already excludes them (libraries/aws_compute_assets.rb:194) and is the right home, but it does not emit iam_instance_profile, and its renderer (render_controls.render) supports only the `empty` and `equals` verbs — its satisfies map is literally {"empty", "equals"} — so `not_empty` would KeyError even once the field exists. Unblocked by one line in aws_compute_assets#instances plus not_empty support in render(); both are code changes, not data.
- **CKV2_AWS_43** (graph-a.yml) — Needs a new predicate on aws_s3_bucket. The check is about ONE grantee URI (.../groups/global/AuthenticatedUsers) in the bucket ACL grants. The stock resource exposes `bucket_acl` as a raw array of Aws::S3::Types::Grant, which no satisfies verb can inspect, and its `public?` predicate is not a substitute: it ORs the AuthenticatedUsers grant together with AllUsers AND with a public bucket policy, so mapping it here would report a policy-public bucket as an ACL finding. Build one grant-inspection helper and this plus CKV_AWS_57 both fall out of it.
- **CKV2_AWS_44** (graph-a.yml) — Needs a new predicate on aws_route_table, and hits the same route-flattening trap as CKV2_AWS_35: the plural's parallel per-column arrays destroy the pairing between vpc_peering_connection_id and destination_cidr_block, which is the entire assertion. The predicate ("any route with vpc_peering_connection_id set whose destination is 0.0.0.0/0 or ::/0") must be built off the singular's `routes`, and no satisfies verb expresses a condition over an array of hashes.
- **CKV2_AWS_45** (graph-joins.yml) — Not a join and not a singleton either, and — unlike most of this slice — not blocked by a missing reader. config DescribeConfigurationRecorders requires no parameters (botocore), so aws_api_assets could enumerate recorders per region and dig recording_group.all_supported through its dotted field path. It is skipped on the ASSERTION instead: that field alone passes a recorder that is configured for everything and STOPPED, because whether it is recording comes from a second call (DescribeConfigurationRecorderStatus) that the api reader cannot make. Half a conjunction rendered as the whole answer is exactly the silent wrong-question failure this repo exists to avoid. The other two shapes do not rescue it either: there is no aws_config_recorders plural in the pack, so the stock shape has nothing to enumerate, and aws_config_recorder is ONE PER REGION while render_singleton emits no region loop at all — a singleton mapping would assess only the region the credentials default to and report that as an account-wide answer, which is exactly the silent under-scoping this profile exists to avoid. It also needs two properties ANDed (recording_group.all_supported on the recorder AND recording on its status); the singular already makes both calls internally (recording_all_resource_types and recording?), so this drops out cleanly once a per-region singleton enumeration exists.
- **CKV2_AWS_46** (graph-a.yml) — The stock field answers only the legacy half, and would fail the modern correct case. CLoudFrontS3OriginConfigWithOAI.json passes on s3_origin_config OR origin_access_control_id. The stock singular builds @s3_origin_access from origin[:s3_origin_config][:origin_access_identity] only (libraries/aws_cloudfront_distribution.rb:66) and never reads Origin.OriginAccessControlId, which is what AWS now recommends — so asserting not_empty on it FAILS every OAC-secured distribution, and also fails any distribution with only custom origins, which Checkov exempts outright. Blocked on the same CloudFront api_spec as CKV2_AWS_32.
- **CKV2_AWS_47** (graph-joins.yml) — Three hops and an assertion about the referent, on top of the wafv2 blocker described under CKV2_AWS_28 (gem present, no resource, no way to pass Scope). Left is cloudfront DistributionSummary.WebACLId; the rules that must contain AWSManagedRulesAnonymousIpList and AWSManagedRulesKnownBadInputsRuleSet are only on GetWebACL(Name, Scope, Id), not on ListWebACLs. Also an identifier hazard worth recording: WebACLId is a WAFv2 ARN for wafv2 and a bare WAF-Classic id for the old service, so the two sides do not always speak the same identifier even within one account.
- **CKV2_AWS_48** (graph-a.yml) — A per-region enumeration turns one Terraform assertion into N-1 guaranteed false failures. The api_spec is buildable — configservice DescribeConfigurationRecorders takes no required arguments, aws-sdk-configservice is in the image, and RecordingGroup.includeGlobalResourceTypes is confirmed in botocore — but the field is per-recorder and therefore per-region, and AWS's own model requires it to be true in exactly ONE region (enabling it everywhere duplicates every global IAM configuration item). Worse, botocore states the global IAM types "can only be recorded by Config in Regions where Config was available before February 2022", so in every newer region the value CANNOT be true. Answering this correctly needs an account-level fold — "at least one recorder in the account sets it" — which no satisfies verb expresses, since every verb here is applied per asset.
- **CKV2_AWS_5** (graph-joins.yml) — Two enumerations and a key match, not a one-hop join. Left speaks a security group id (aws_security_groups is an AwsCollectionResourceBase that calls populate_filter_table_from_response, so its columns are the pluralised keys of describe_security_groups — group_ids). The only deployed evidence of attachment is ec2.NetworkInterface.Groups, and the singular aws_ec2_network_interface speaks a network_interface_id (eni-…): it takes required: [:network_interface_id] and calls describe_network_interfaces with network_interface_ids: [opts[...]]. It cannot be looked up by group id. aws_ec2_network_interfaces does register a `groups` column, so both sides exist — but matching them needs the right side enumerated wholesale and keyed, which the stock shape cannot express.
- **CKV2_AWS_58** (graph-b.yml) — Neptune deletion protection has no reader available to a data-only change. inspec-aws ships no aws_neptune_* resource (confirmed by listing the vendored pack), api_specs.yml has no aws_neptune_cluster entry, and aws-sdk-neptune is NOT in tools/image_gems.txt — an api spec naming it would be refused, and if it were not the LoadError would be rescued into unreadable_regions and read as Not Applicable. Reading Neptune clusters through aws_rds_clusters was rejected: DescribeDBClusters returns Aurora and DocumentDB clusters as well, the mapping schema has no `where engine == neptune`, and the control would silently assert against every RDS cluster in the account. Needs the gem in the image plus an api spec, or a stock resource upstream.
- **CKV2_AWS_60** (graph-b.yml) — The mapping itself is sound — aws_rds_instances.db_instance_identifiers -> aws_rds_instance(db_instance_identifier:).copy_tags_to_snapshot — but the CATALOGUE entry cannot be rendered. checkov_catalog.yml gives CKV2_AWS_60 `resources: []` and `tf_docs: null`, and render_controls.render_fix does `list(entry['tf_docs'].values())[0]` whenever no fixes matched a declared resource type, which raises AttributeError on None. Since resources is empty, no fixes entry can ever match, so the crash is unavoidable from data alone and it would abort the whole render, leaving controls/ half-written. Blocked on a one-line guard in render_fix/render_stock (or on the catalogue learning this check's resource types). Same blocker as CKV2_AWS_65 and CKV2_AWS_66.
- **CKV2_AWS_62** (graph-b.yml) — S3 event notifications need a new predicate on aws_s3_bucket. The vendored resource exposes no notification reader at all (its methods are bucket_acl, bucket_ownership_controls, public?, has_access_logging_enabled?, prevent_public_access?, has_default_encryption_enabled?, has_versioning_enabled?, has_secure_transport_enabled?, bucket_policy, bucket_lifecycle_rules, tags), and this slice writes data, not library code. GetBucketNotificationConfiguration answers it in one call per bucket and returns 200 with an empty body when there are none, so the predicate must treat empty as false rather than nil.
- **CKV2_AWS_65** (graph-b.yml) — Blocked exactly as CKV2_AWS_60 is: `resources: []` and `tf_docs: null` in checkov_catalog.yml make render_fix raise AttributeError on None. The reader side is confirmed ready — aws_s3_bucket#bucket_ownership_controls exists and returns OwnershipControls.Rules[0].ObjectOwnership as a String, so `equals BucketOwnerEnforced` with `scope: global` would be correct the moment the renderer stops crashing. Note for whoever lands it: that reader indexes [0] unguarded, so a bucket that never had ownership controls set raises OwnershipControlsNotFoundError, which catch_aws_errors turns into a failed resource — a visible failure, not a false pass.
- **CKV2_AWS_66** (graph-b.yml) — Two independent blockers. (1) Same catalogue defect as CKV2_AWS_60/65: `resources: []` and `tf_docs: null`, so render_fix raises. (2) There is no reader. mwaa ListEnvironments returns NAMES ONLY and WebserverAccessMode lives on GetEnvironment(Name).Environment, which api_specs cannot express — the spec reader makes one list call and extracts fields, it never follows up per row — and inspec-aws ships no aws_mwaa_* resource. Needs a small singular resource written upstream or in libraries/.
- **CKV2_AWS_69** (graph-joins.yml) — The valuable member of the RDS-parameter family, and still blocked: the values it needs (rds.force_ssl, require_secure_transport, db2comm) come from DescribeDBParameters, which no stock resource calls and which the api reader cannot call because it takes a DBParameterGroupName argument. It also needs a per-family branch on the MATCHED RIGHT ROW (DBParameterGroupFamily decides which parameter name to read), which is the "assert about the referent" form the one-hop shape cannot express even once a reader exists.
- **CKV2_AWS_7** (graph-joins.yml) — Both sides unreachable. aws_emr_clusters yields cluster_ids/cluster_arns and registers no security-group column, and the singular aws_emr_cluster does NOT read ec2_instance_attributes at all — it assigns a fixed list of attr_readers (status, cluster_arn, applications, roles, kerberos, log_uri…) and never calls create_resource_methods, so the five SG members Checkov follows (emr_managed_master/slave, service_access, additional_master/slave) are not exposed by any resource in the pack. Even with them, the assertion is on the matched RIGHT row (the SG's ingress carries no 0.0.0.0/0), which is the "follow then assert about the referent" form the stock shape has no way to say.
- **CKV2_AWS_71** (graph-b.yml) — WITHDRAWN IN ADVERSARIAL REVIEW. The assertion itself is sound — the live aws_acm_certificate api spec declares `id: domain_name`, so AwsApiAssets#row_for sets row[:id] to the domain name as a never-nil String and `excludes '*'` is a correct substring test on it. What is NOT sound is the population it runs over. AwsApiAssets#collect invokes the spec's list call with NO arguments, and botocore acm documents the default for ListCertificates' `Includes.keyTypes` filter as "Default filtering returns only RSA_1024 and RSA_2048 certificates that have at least one domain." So every EC certificate (EC_prime256v1, EC_secp384r1, EC_secp521r1) and every RSA_3072/RSA_4096 certificate is invisible to the enumeration — permanently, in every account, regardless of size. A wildcard certificate on an EC key is exactly the modern ALB/CloudFront default, and it would render as a clean pass; an account whose certificates are ALL EC renders the control NOT APPLICABLE — "this rule does not apply here" for an account full of certificates. That is the failure mode the api reader's unreadable_regions guard exists to prevent, and this one walks past it because the list call SUCCEEDS. Fixing it means teaching api_specs to carry list arguments (or adding a keyTypes-complete spec), which is a change to a LIVE spec and to the reader — library work this slice cannot do, and merge_proposals correctly refuses a staging file that redefines a live spec. Two notes for whoever lands it: (1) the same defect makes the live spec's `key_algorithm` field near-vacuous, since it can only ever report RSA_1024 or RSA_2048; (2) once the enumeration is complete, CertificateSummary already carries SubjectAlternativeNameSummaries, so the SAN half of this rule needs no DescribeCertificate call — only the any-element verb named in the CKV2_AWS_72 entry below. The Terraform fix example is retained in `fixes:` so it is not lost; an unreferenced fix entry is precedented here.
- **CKV2_AWS_72** (graph-b.yml) — Needs a verb that does not exist. @custom_origin_protocol_policies is an ARRAY with one entry per custom origin, and the requirement is "no element of this array is in [http-only, match-viewer]". `not_in_list` compares a SCALAR against a list — it renders `should_not be_in [...]`, and an Array is never `in` a list of Strings, so the assertion passes for every distribution including the non-compliant ones: a control that cannot fail. Needs an any-element / set-intersection verb (`excludes_any`, or `not_in_list` taught to distribute over an array subject) in matcher_for. The same verb closes the subject_alternative_names half of CKV2_AWS_71.
- **CKV2_AWS_76** (graph-joins.yml) — Same as CKV2_AWS_47 with an ALB left side. The identifiers DO line up here — aws_albs.load_balancer_arns yields exactly the ResourceArn that wafv2.get_web_acl_for_resource takes, so this becomes a straight one-hop the moment a wafv2 singular exists. GetWebACLForResource requires only ResourceArn (botocore), so unlike ListWebACLs it needs no Scope, and aws-sdk-wafv2 is in the image — what is missing is a resource that does a per-id LOOKUP, which the api reader is not: it enumerates a list operation and cannot be handed an id. The assertion is also on the returned WebACL's rule names rather than on the link.
- **CKV2_AWS_78** (graph-joins.yml) — Identical to CKV2_AWS_76 with an AppSync left side, and worse off: neither the appsync enumeration nor the wafv2 lookup exists in the pack.
- **CKV2_AWS_8** (graph-joins.yml) — No AWS Backup resource exists in the vendored stock pack — but, correcting the first draft of this entry, that is NOT the blocker. aws-sdk-backup is in tools/image_gems.txt, tools/api_specs.yml already carries an aws_backup_vault row on Aws::Backup::Client, and botocore confirms backup ListProtectedResources takes no required parameters, so aws_api_assets — which calls its list operation with no arguments — can reach it. The blocker is the ASSERTION shape: the api reader enumerates ONE operation and asserts a flat field per row, so enumerating backup.list_protected_resources would assert something about the resources that ARE protected and say nothing about the RDS clusters that are not. Needs two enumerations matched on the cluster arn. Deliberately NOT substituted with aws_rds_cluster.backup_retention_period: RDS automated backups are a different mechanism from an AWS Backup plan selection, and silently answering a different question is the failure mode this repo is built to avoid.
- **CKV2_AWS_9** (graph-joins.yml) — Same blocker as CKV2_AWS_8 — the Backup SDK is present and ListProtectedResources is callable with no arguments; what is missing is a shape that can match two enumerations — plus a key mismatch that would be silent if it were built anyway: left speaks a volume id (vol-…) because ec2.Volume carries no Arn member, while backup ListProtectedResources keys on ResourceArn. A join whose keys never match reports every volume as unprotected — a 100% finding that looks like a result, not like an error.
- **CKV_AWS_102** (batch.yml) — aws-sdk-neptune is not in the auditor image, so merge_proposals refuses the aws_neptune_cluster_instance api spec. The RDS fallback (aws_rds_instances -> aws_rds_instance.publicly_accessible) cannot be restricted to engine == neptune in either shape and would be identical to the already-reviewed CKV_AWS_17, so it would look like Neptune coverage while providing none. Unblocks with the gem; the spec needed is Aws::Neptune::Client#describe_db_instances -> db_instances, scope regional, id db_instance_identifier, arn db_instance_arn, field publicly_accessible, equals false.
